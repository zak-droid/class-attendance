# בדיקות משתמש בדפדפן

הבדיקות מריצות את קוד React של האפליקציה בדפדפן Chromium אמיתי דרך Playwright, בשני גדלי מסך: מחשב וטלפון. השרת עולה ונסגר אוטומטית.

התקנה ראשונה מתוך תיקיית הפרויקט (Node.js 22 ומעלה):

```sh
npm ci
npx playwright install chromium
```

הרצה חוזרת:

```sh
npm run test:e2e
```

צפייה בדוח: `npx playwright show-report`. להרצה עם חלון דפדפן: `npm run test:e2e -- --headed`. בדיקות יחידה ובנייה: `npm test`.

התרחישים רצים בשני גדלי המסך: טעינת מסך היום, שינוי שם קורס ושמירתו לאחר רענון, הצגת שגיאת שמירה וניסיון חוזר, העלאת קובץ CSV עם עמודות שם פרטי ומשפחה, ורצף נוכחות הכולל איחור, הערה, סיום, עריכת תאריך קודם וסינון היסטוריה לפי תלמיד. תאריך הבדיקה קבוע כדי שהתוצאות לא יהיו תלויות ביום ההרצה.

תמונות נשמרות בתוך `test-results`; בעת כישלון נשמר גם trace שניתן לפתוח דרך דוח HTML.

## גבולות הבדיקה

קובץ התצורה של הבדיקות מחליף את מודול Supabase במימוש מדומה. הנתונים נשמרים ב-sessionStorage של הקשר הדפדפן המבודד, כך שרענון שומר את השינויים וכל בדיקה חדשה מתחילה בנתונים נקיים. אין כאן מסד Supabase אמיתי; הבדיקות אינן מוכיחות תקינות הרשאות RLS, SQL, סנכרון בין מכשירים או WebAuthn פיזי. כל בקשות HTTPS חסומות בזמן הטסטים, והחשבון מחובר מראש כחשבון בדיקה.

להפעלה ידנית עם נתוני בדיקה: `npm run dev:e2e`, ואז פתיחת `http://127.0.0.1:5179`. תצורת הייצור אינה משתמשת במודול המדומה.

בסביבת Codex עם הגבלת sockets יש להריץ את הפקודה בהרשאה המאפשרת תהליכי דפדפן ושרת מקומי. אין צורך לשנות חומת אש או לפתוח שרת לרשת: השרת מאזין ל-127.0.0.1 בלבד.

Workflow של Pull Request מריץ את הבדיקות ומעלה דוח. תהליך הפריסה הקיים כולל אותן לפני פרסום, כך שכישלון יעצור את הפריסה.


נוספו בדיקות לסיום מפגש אחרי רענון, תלמיד חדש במפגש פתוח, יצירת נוכחות היסטורית, שמירת מידע משותף לאחר ניקוי המטמון, משוב שאינו משלים מטלה, סנכרון מפגש שנפתח ללא רשת, שגיאות שמירה, ייבוא XLSX וקריאת קובץ CSV שהורד בפועל.
